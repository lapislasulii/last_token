# Сопоставление «один к одному» в redetect

## Что исправлено

Метка error ставится по правилу из TASK.txt: на кадре строятся взаимно однозначные пары предсказанных и ручных боксов
одного класса с IoU не ниже 0.6, сначала максимизируется число пар, затем суммарный IoU. Раньше `redetect.py`
считал бокс подтверждённым, если рядом был **любой** наш бокс с IoU >= 0.6. Два дубля на одном нашем боксе оба
получали «верно», хотя по правилу один из них — ошибка.

Теперь `agreement_features` повторяет официальное правило, подставляя боксы нашего детектора на место ручных
(`linear_sum_assignment`, вес `1000 + IoU` для допустимых пар). Признак `matched` заменяет `iou_same < 0.6`
в основном скоре и в доле D ансамбля. Порог уверенности наших боксов прежний — 0.05. Новых параметров нет,
по отложенному дню ничего не подбиралось.

`test.csv` и `train.csv` содержат все детекции оцениваемых классов на целевых кадрах (вне их только столы на test),
поэтому дубли видны функции целиком.

## Test

Ансамбль base+s1+s2 с вето (Public 0.89753) пересобран с правилом один к одному:
`submissions/redetect_strong_ens-base-s1-s2_1to1_veto_veto.csv`. Изменились 8 из 362 боксов, все поднялись в очереди
(5 кистей, 3 чашки; это дубли на одном боксе нашего детектора). Аудитор сабмитов: формат OK, Spearman с прежним
файлом 0.994.

```sh
python tools/redetect.py submit --tag strong --members base s1 s2
python tools/blend_veto.py test submissions/redetect_strong_ens-base-s1-s2_veto.csv
```

Пересобранный без правки файл совпадает с отправленным по формуле, но не по SHA256 (вероятно, формат чисел
другой версии pandas); поштучно с замороженным файлом не сверялся.
