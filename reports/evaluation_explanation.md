# Проверка предсказаний и сравнение моделей

## 1. Цель работы

Цель — создать единый инструмент для проверки предсказаний разных моделей и сравнения их качества на одинаковом наборе данных.

Для этого был разработан скрипт `tools/evaluate_predictions.py`, который позволяет оценивать предсказания, проверять корректность входных данных и сравнивать результаты с базовой моделью (baseline).

## 2. Как работает оценщик

На вход скрипт получает CSV-файл с предсказаниями. В нём обязательно должны быть два столбца:

- `id` — идентификатор объекта;
- `score` — оценка модели от 0 до 1.

Разметка загружается из `train.csv`, а информация о датах и кадрах — из `train_frames.csv`.

Сопоставление объектов выполняется по `id`, а не по порядку строк. Это позволяет корректно оценивать предсказания, даже если строки в разных CSV расположены в разном порядке.

Перед оценкой скрипт проверяет:
- отсутствие повторяющихся идентификаторов;
- отсутствие пропущенных и неизвестных объектов;
- отсутствие `NaN` и `inf`;
- нахождение всех оценок в диапазоне от 0 до 1.

Объекты класса `table` и другие исключённые правилами проекта классы не участвуют в оценке.

## 3. Метрики

Основная метрика — **Average Precision (AP)**. Она показывает, насколько хорошо модель ранжирует объекты с ошибками относительно объектов без ошибок.

AP рассчитывается отдельно для каждого дня:
- 25 октября 2026 года;
- 26 октября 2026 года.

Дополнительно рассчитываются:
- **Mean AP** — среднее значение AP за два дня;
- **Worst AP** — худшее значение AP среди двух дней;
- **Delta** — изменение результата относительно baseline.

В качестве baseline используется оценка `1 - confidence`, то есть обратная уверенность исходной модели.

Также выводится диагностика по классам: количество объектов, количество ошибок и AP для каждого класса.

## 4. Проверка корректности

В скрипт встроены автоматические тесты (`selftest`), которые проверяют:
- независимость результата от порядка строк;
- корректную обработку одинаковых оценок (tied scores);
- сопоставление объектов по `id`;
- обнаружение дубликатов;
- обнаружение пропущенных и неизвестных идентификаторов;
- обнаружение некорректных значений `NaN`, `inf` и оценок вне диапазона `[0, 1]`.

Все тесты успешно пройдены.

Дополнительно была выполнена проверка baseline и временной модели на полном OOF-наборе из 198 оцениваемых объектов. Результаты совпали с контрольными значениями проекта с точностью до допуска `1e-6`.

## 6. Как запустить

Все команды выполняются из корневой папки проекта.

```powershell
# Проверка встроенных тестов
python tools/evaluate_predictions.py selftest

# Информация об оцениваемом наборе
python tools/evaluate_predictions.py info

# Оценка baseline
python tools/evaluate_predictions.py baseline --mode oof

# Обучение и оценка временных моделей
python tools/train_temporal.py

# Оценка выбранной временной модели
python tools/evaluate_predictions.py score oof/temporal_core_c1_blend.csv --mode oof --name temporal_core_c1_blend
```

Результаты отдельных запусков сохраняются в `outputs/evaluation/`. Сводная таблица экспериментов находится в `outputs/evaluation/experiments_summary.csv`.

## 7. Ограничения

Оценщик проверяет качество готовых предсказаний, но сам по себе не гарантирует отсутствие утечки данных. Для этого необходимо отдельно проверять код обучения и способ формирования OOF-предсказаний.

В Git сохраняются код оценщика, описание работы и сводные результаты. Индивидуальные предсказания, модели и файлы отправки на платформу остаются локально.

## 8. Итог простыми словами

Мы сделали программу, которая позволяет одинаково проверять разные модели и сравнивать их между собой.

Программа проверяет, что все объекты на месте, нет повторов и неправильных оценок. Затем она рассчитывает качество модели отдельно за каждый день и сравнивает его с базовым вариантом.

Сначала мы проверили baseline — он показал средний результат **0.812772**. Затем проверили модели с временными признаками. Лучшей оказалась `temporal_core_c1_blend` со средним результатом **0.840175**.

Она улучшила результат на обоих днях. Все автоматические проверки прошли успешно, а полученные значения совпали с контрольными.

В итоге у команды теперь есть единый инструмент, с помощью которого можно проверять новые предсказания и объективно сравнивать качество моделей.
