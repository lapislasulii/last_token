# «Второе мнение»: свой детектор на ручных боксах — 13 ноября

**Итог: гипотеза не подтвердилась.** Отдельно сигнал заметно хуже бейзлайна, в смеси с ним — на уровне шума. Для `person` сигнала нет. Как основной подход не используем.

## Идея

Метка `error` определена через ручные боксы: детекция верна, если сопоставилась с ручным боксом того же класса при IoU ≥ 0.6. Если обучить свой детектор рисовать боксы по конвенции разметчиков (person целиком, с ногами под столом), то расхождение с ним должно указывать на ошибку исходного детектора. Особенно ожидали поймать главную ошибку кейса — человека, обрезанного по краю стола.

Детектор — не замена исходному, а контролёр: score каждой исходной детекции строится по согласию двух детекторов.

## Как проверяли

- Модель: YOLO11s, публичные COCO-веса Ultralytics (`yolo11s.pt`, https://github.com/ultralytics/assets/releases), `ultralytics==8.3.40`.
- Обучение только на `human_boxes_train.csv`, классы `person`, `nude_hands`, `cup`, `tray`. 25.10: 42 кадра, 80 боксов; 26.10: 42 кадра, 160 боксов.
- Честное разделение по дням: детектор, обученный на одном дне, размечает кадры другого. Эпохи фиксированы (60), другой день не использовался ни для отбора эпох, ни для порогов.
- imgsz 1280, batch 2, seed 0, Apple M4 (MPS): ~20 минут на день.
- Для каждой исходной детекции: лучший IoU с нашим боксом того же класса (`iou_same`), макс. уверенность нашего бокса среди пар с IoU ≥ 0.6 (`match_conf`), совпадение с боксами другого класса. Score без обучаемой склейки — заранее выбранные эвристики, чтобы не подгонять под два дня.

## Почему не сработало

Для `person` наш детектор согласен с верными и ошибочными боксами одинаково: медианный `iou_same` 0.64 у верных и 0.62 у ошибочных. У четверти верных боксов людей `iou_same` около 0.1 — наш детектор человека не нашёл или нарисовал иначе.

Подход требует, чтобы свой детектор рисовал людей точнее порога IoU 0.6. На 28–54 примерах людей за день он выучил, где примерно человек, но не как именно разметчик рисует границы: даже на своём обучающем дне mAP50-95 около 0.6. Проблема в объёме разметки, а не в идее.

## Что можно было бы попробовать (не делали)

- Крупнее модель (`yolo11m`), больше эпох, обучение на GPU — шансы для `person` невысокие по той же причине.
- Использовать согласие только для `cup` / `nude_hands` как признак внутри существующей модели.
- Псевдоразметка machine pool этим же детектором не имеет смысла: метки будут не лучше самого детектора.

## Воспроизведение

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python "ultralytics==8.3.40" torch torchvision pandas scikit-learn
.venv/bin/python tools/redetect.py build
.venv/bin/python tools/redetect.py train --epochs 60 --batch 2   # --device 0 --batch 8 на NVIDIA
.venv/bin/python tools/redetect.py predict
.venv/bin/python tools/redetect.py eval
```

Датасет — в `data/rascar-hack-case-1/`. Веса, детекции и OOF-признаки сохраняются локально в `outputs/redetect/` и в Git не попадают.
