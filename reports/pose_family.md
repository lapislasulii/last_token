# Голос позы у людей в зале: «семьи поровну»

Если у людей вне окна дать позе вес наравне со всем YOLO-ансамблем (D' = (Y + P) / 2 вместо (6·Y + P) / 7), локальный AP растёт с 0.9258 / 0.9257 до 0.9334 / 0.9344 (+0.0082 в среднем). Критерий пройден по всем четырём пунктам. И на train, и на test меняются только люди вне окна. Test-файл собран: `submissions/pose_family_w050_on_flip_pose.csv`, изменилось 39 строк из 362. На Kaggle не отправлялся.

## Идея и почему «семьи поровну»

Сейчас у людей вне окна (центр рамки ≥ 330 px) доля возражений считается так: `D' = (6·Y + P) / 7`.

- **Y** — доля шести YOLO-голосов (`base s1 s2` и их отражения), у которых бокс не нашёл пару один к одному с IoU ≥ 0.6.
- **P** — голос модели позы YOLO11x-pose (`tools/person_vote.py`): полный кадр, уверенность ≥ 0.5.

Шесть YOLO — одна архитектура, одни данные, разные seed и отражения. Ошибаются они согласованно, и шесть голосов по сути один голос, повторённый шесть раз. Поза — независимая модель, на наших кадрах не дообучалась. В формуле лидера её голос весит 1/7 и тонет в согласованном мнении YOLO. Принцип «каждая семья моделей весит поровну» команда уже заранее заложила в протокол RF-DETR (`docs/tasks/rfdetr_judge.md`).

**Кандидат** (зафиксирован до запуска): у людей вне окна `D' = (Y + P) / 2`, то есть вес позы w = 1/2. Всё остальное как у лидера:

- люди у окна: D' = Y (там позу слепит засвет, P исключён и раньше);
- остальные классы: D' = Y;
- вето: max(V, L);
- `score = (1 − confidence + D' + 2·max(V, L)) / 4`.

## Урок RF-DETR: меняются только люди вне окна

RF-DETR у команды локально выиграл (0.94658 / 0.92671), а на Public получил 0.90664 против 0.92465 у опоры (`reports/predictions_release.md` в `origin/main`). По разбору команды, на test он сильнее всего переставил кисти и подносы, хотя локальный выигрыш был на людях.

Здесь это исключено проверкой в коде (`assert`): между опорой и кандидатом скор меняется только у людей вне окна.

- **Train:** изменилось 43 строки — все люди вне окна, у которых Y ≠ P (людей вне окна 62).
- **Test:** изменилось 39 строк — ровно люди вне окна с Y ≠ P. Все 20 строк, сдвинутых в очереди больше чем на 20 мест, — люди в зале.

## Ворота

Участники `base s1 s2 base_flip s1_flip s2_flip`, командный кэш вето из `origin/main` (хэши объектов git совпадают).

- Опора с w = 1/7 дала **0.92579 / 0.92565**, ровно как опубликованные числа команды (`assert` с допуском 1e-4).
- Опора совпадает с `person_vote.scores(..., legs=True, skip_window=True)` (`assert`).
- Копия `pose_vote` с параметром порога при conf 0.5 совпадает с оригиналом (`assert`).

## Чувствительность к порогу P (диагностика)

Порог уверенности позы 0.5 команда выбирала с оглядкой на train. Опора и кандидат пересчитаны с одним и тем же P:

| conf позы | P = 1 у людей вне окна | Опора | Кандидат | Прирост по дням | Прирост среднего |
|---:|---:|---|---|---|---:|
| 0.4 | 18 | 0.9258 / 0.9257 | 0.9334 / 0.9344 | +0.0076 / +0.0087 | +0.0082 |
| 0.5 | 20 | 0.9258 / 0.9257 | 0.9334 / 0.9344 | +0.0076 / +0.0087 | +0.0082 |
| 0.6 | 22 | 0.9258 / 0.9255 | 0.9317 / 0.9337 | +0.0059 / +0.0082 | +0.0071 |

При 0.4 голос P меняется у двух боксов, но AP по дням тот же, что при 0.5. Эти боксы не меняют порядок ошибок относительно верных.

## Люди вне окна: Y × P

Боксов / ошибок:

| День | Y | P = 0 | P = 1 |
|---|---|---:|---:|
| 25.10 | 0 | 6 / 0 | — |
| 25.10 | дробный | 11 / 2 | 3 / 3 |
| 25.10 | 1 | 1 / 0 | 3 / 3 |
| 26.10 | 0 | 6 / 2 | 3 / 3 |
| 26.10 | дробный | 16 / 4 | 7 / 5 |
| 26.10 | 1 | 2 / 0 | 4 / 4 |

**Оба дня: при P = 1 ошибок 18 из 20, при P = 0 — 8 из 42.** Внутри каждого уровня Y голос позы разделяет ошибки лучше, чем сам Y. При Y = 1 и P = 0 ошибок 0 из 3. При Y = 0 и P = 1 ошибок 3 из 3. Поэтому вес позы наравне с ансамблем и помогает.

## Изменения на test

Сборка из файлов лидера из `origin/main` (локальные копии в `outputs/pose_family/`):

- Из файла без позы восстановлены Y (сетка 1/6) и V. Из файла с позой — D' и V' = max(V, L). Для людей вне окна `P = 7·D' − 6·Y` ∈ {0, 1}, `L = 1` там, где V' = 1 и V = 0.
- **Ворота сборки:** пересобранный лидер совпадает с файлом лидера с позой с точностью 1e-16. В файле лидера V = 1 у 47 боксов, L = 1 у 3, P = 1 у 23 из 87 людей вне окна.
- Изменилось **39 строк** из 362: все — люди вне окна с Y ≠ P. Из них **поднялись 23** (P = 1: поза не видит человека там, где большинство YOLO его подтверждает) и **опустились 16** (P = 0: поза видит, а часть YOLO возражает).
- Spearman с лидером **0.9964**. Больше чем на 20 мест сдвинулись **20 строк, все — люди в зале**. Кисти, чашки, подносы и люди у окна не тронуты.
- Файл: `submissions/pose_family_w050_on_flip_pose.csv`. Проверено: 362 уникальных id, совпадение с `sample_submission.csv`, скоры конечные и в [0, 1].

Сильнее всего поднялись 7 людей с Y = 0 и P = 1 (все шесть YOLO подтверждают, поза не видит), например `58d3aa8c1e24141f`: 0.0632 → 0.1525. На train такие боксы оказывались ошибками в 3 случаях из 3.

## Ограничения

1. **Подбор на train.** Порог уверенности P (0.5) и граница окна (330 px) выбирались с оглядкой на train. Прирост поэтому может быть оптимистичным. Сам вес 1/2 задан до запуска из принципа «семьи поровну», а не подобран.
2. **Public почти не видит людей.** По опыту команды, изменения по людям на Public почти не отражаются: добавление позы дало 0.92465 → 0.92465. Kaggle этот вариант, скорее всего, не подтвердит и не опровергнет, эффект будет виден только на Private.
3. **Дневные модели против итоговых.** Локальная проверка идёт на дневных моделях (каждая не видела день бокса), а test — на итоговых, обученных на обоих днях. Итоговые YOLO могут согласоваться с позой иначе.
4. **Мало людей вне окна:** 62 бокса train, 26 ошибок. Bootstrap 25.10 широкий: от −0.0041 до +0.0357.
