# Как принять результаты автоматической и ручной проверки

Вова готовит приблизительные ответы, Маша проверяет, каким видам этих ответов можно доверять. Отсутствие объекта у второго детектора — не автоматическое доказательство ошибки первого. Неуверенные случаи оставляем без ответа.

Передача: локальный CSV с полями id, frame_id, pseudo_error (0/1 или пусто), pseudo_confidence (0..1), review_status (accepted/rejected/uncertain), annotator_model, annotation_train_days. Последнее поле — JSON-список UTC-дней, чьи ручные ответы использованы для обучения или выбора настроек разметчика. Для действительно готовой модели без подбора на train — []. Уверенность разметчика не считается измеренной вероятностью правильности.

accepted означает, что пример прошёл согласованные критерии качества по результатам ручной проверки; это не утверждение, что каждый такой бокс просмотрен человеком. Полезно дополнительно хранить review_method и комментарий. Проверенную человеком выборку и автоматически допущенные строки анализировать раздельно.

Запуск: `python tools/prepare_pseudo_labels.py путь_к_файлу.csv`. Проверяются ID и их кадры по исходному machine pool, метки, диапазоны уверенности и происхождение разметки. Скрипт исключает официальные train/test кадры и их предоставленный контекст; для каждой проверки по дню исключает весь этот день из pool, а также ответы разметчика, обученного/настроенного на этом дне. Неопределённые и отклонённые строки не допускаются.

Получаются два локальных списка допустимых примеров в outputs/pseudo_ready/. Это подготовка входа, ещё НЕ обучение на pool. Если все ответы получены разметчиком, обученным на обоих официальных днях, для честной проверки нужны отдельно два разметчика — иначе скрипт закономерно не допустит такие строки.

После получения реальных файлов: извлечь для них признаки выбранного encoder с тем же способом подготовки картинки. Сравнить официальное обучение с тем же обучением плюс небольшая проверенная порция pool; считать AP только на официальном отложенном дне. Заранее зафиксировать размер порции и меньший вес приблизительных ответов. Число pseudo-строк не должно автоматически сделать их важнее официальных меток. Итоговый критерий — прирост поиска ошибок на другом дне, а не число размеченных кадров.

Пока реальных файлов нет, качество меток и пользу их добавления проверить невозможно. Ничего не отправлять в публичный Git: индивидуальные таблицы и кадры остаются локальными. Скрипт принимает заявленное происхождение разметки; доказать правдивость annotation_train_days по CSV нельзя, это проверяется по коду разметчика.
