# Как работает решение и что делать дальше

## Что мы решаем

Нам уже дали найденные объекты: координаты прямоугольника, класс и уверенность детектора. Мы не ищем объекты заново и не исправляем координаты. Мы выставляем каждому готовому боксу score: чем выше, тем раньше оператору стоит проверить его на ошибку. error=1 означает ошибку, error=0 — правильный бокс. Качество измеряется Average Precision (AP).

## Лучший отправленный вариант

**DINOv2-small с отмеченным контекстом, marked_context_l1: Public AP 0.66398.** Baseline 1-confidence получил 0.64114. Private неизвестен.

1. Вырезаем область вокруг бокса, увеличив ширину и высоту в 1.5 раза.
2. Сохраняем пропорции, дополняем изображение до 224×224 и рисуем исходную границу бокса красной линией. Красный цвет здесь НЕ означает ошибку: он одинаков для всех примеров.
3. Готовый encoder превращает картинку в числовые признаки. Его веса заморожены, мы его не дообучаем.
4. Обучаем StandardScaler и PCA, оставляя 16 визуальных компонент.
5. Небольшая линейная модель корректирует исходный риск 1-confidence. Формула: sigmoid(logit(1-confidence) + признаки × веса). Веса обучаются на официальном error; штраф lambda=1 ограничивает величину поправки.

Модель не получает ручные боксы, причины ошибок или отдельный класс объекта как вход. Ручные боксы нужны для диагностики других экспериментов. Итог — только подозрительность, не объяснение причины.

## Что сравнили

Ниже одинаковый штраф lambda=1. Это локальная проверка: обучение на одном UTC-дне, оценка на другом и наоборот. Масштабирование и PCA тоже обучаются только внутри обучающего дня. Изображения test проходят только через замороженный encoder. Table исключён. Всего 198 train и 362 test детекции.

| Encoder | AP 25 октября | AP 26 октября | Среднее | Kaggle Public |
|---|---:|---:|---:|---:|
| DINOv2-small с рамкой | 0.863048 | 0.781325 | 0.822187 | **0.66398** |
| DINOv2-base с рамкой | 0.863365 | 0.768754 | 0.816059 | Не отправлен |
| DINOv2-large с рамкой | 0.872577 | 0.776306 | **0.824441** | Не отправлен |
| CLIP ViT-L/14 с рамкой | 0.867744 | 0.768759 | 0.818251 | Не отправлен |

Также проверяли lambda=10: все результаты есть в reports/encoder_comparison.md и reports/clip_comparison.md. Публикуем головы lambda=1 для сопоставимого воспроизведения; не все лучшие по отдельным метрикам варианты сохранены как готовые артефакты. CLIP использует свою нормализацию и CLS после layer norm, без текстовой ветки. Смесь CLIP и Small не улучшила средний AP.

Large немного лучше в среднем, но проигрывает Small на втором дне. Размер encoder не гарантирует улучшения. Дни многократно использовались для выбора вариантов, поэтому локальные преимущества могут быть переоценены. Локальный AP и Public нельзя сравнивать как одну выборку.

## Главные выводы анализа ошибок

У текущего контекста без рамки 20 из 34 ошибок в нижней половине очереди оказались людьми. В этой группе 9 боксов предположительно слишком маленькие, 6 слишком большие, 2 смещены и 3 имеют неустановленную причину. Это диагностические геометрические гипотезы, не независимая ручная разметка причин.

Специалист по геометрии person не помог: поднял больше нужных ошибок, но вместе с правильными людьми, вытесняя другие ошибки. Все четыре сочетания ухудшили AP обоих дней. Временные модели и классификатор причин тоже не обошли baseline на Public. Эти отрицательные результаты сохраняем, чтобы не повторять эксперименты.

## Как запустить

Датасет положить в data/rascar-hack-case-1/. Команды выполнять из корня репозитория. Проверено на Python 3.13 и NVIDIA RTX 5070 Ti Laptop GPU. CPU допускается кодом, но скорость не проверялась.

```powershell
python -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install -r model_releases/requirements-visual.txt
python tools/train_marked_context.py --encoder small --batch-size 8
python tools/predict_marked.py model_releases/marked_context_l1.joblib
```

Первый запуск скачивает публичные веса, извлекает train/test признаки, воспроизводит OOF и обучает локальную голову. Вторая команда явно использует опубликованную голову с полученным кэшем. Результат — submissions/marked_context_l1.csv. Скрипты ничего не отправляют на Kaggle.

Для остальных encoder:

```powershell
python tools/train_marked_context.py --encoder base --batch-size 8
python tools/predict_marked.py model_releases/marked_context_base_l1.joblib
python tools/train_marked_context.py --encoder large --batch-size 4
python tools/predict_marked.py model_releases/marked_context_large_l1.joblib
python tools/train_marked_context.py --encoder clip --batch-size 4
python tools/predict_marked.py model_releases/marked_context_clip_l1.joblib
python -m unittest discover -s tests -v
```

В model_releases лежат только небольшие обученные головы (scaler, PCA, коэффициенты и описание encoder), не полные CV-веса. Полные веса автоматически скачиваются в weights/hf. Источники: [DINOv2-small](https://huggingface.co/facebook/dinov2-small), [base](https://huggingface.co/facebook/dinov2-base), [large](https://huggingface.co/facebook/dinov2-large), [CLIP](https://huggingface.co/openai/clip-vit-large-patch14). Revision сохранены в артефактах; SHA-256 голов — model_releases/marked_metadata.json. Не загружайте произвольные недоверенные joblib-файлы.

Кадры, датасет, кэш, индивидуальные предсказания и токены не публикуются. Модели — итог обучения на всём train, оценивать их на том же train как на отложенной выборке нельзя. Для оценки используйте OOF.

## Что предлагаем дальше

1. Обсудить отправку Large: он лучший среди новых вариантов по среднему локальному AP, но не по обоим дням. Решение об отправке ещё не принято.
2. Проверить отдельные признаки внутри и вокруг бокса вместо нарисованной рамки.
3. Machine pool подключать под конкретную задачу: там машинные предсказания, а не достоверные метки ошибок. Валидационный день и его контекст должны оставаться вне обучения.

Текущий ориентир — уже отправленный Small с рамкой. При подготовке этой публикации новых отправок Kaggle не было.
