# Задание 1: единая проверка предсказаний

## Идея

Сделать проверяющую программу для ответов любой модели. Она получает `id,score`, находит правильные метки и показывает, лучше ли модель baseline и текущего временного решения.

«Отложенный день»: модель обучена на 25 октября и отвечает на 26 октября; затем наоборот. В оценку передаются эти ответы. OOF — общий файл таких предсказаний: каждая строка предсказана моделью, которая не обучалась на её дне.

## Что уже есть

`tools/train_logreg.py` и `tools/train_temporal.py` уже считают AP внутри экспериментов. Задача — сделать общий инструмент, чтобы новые методы проверялись одинаково. Текущие OOF можно воспроизвести командой `python tools/train_temporal.py`; они сохраняются локально в `oof/`.

## Что именно сделать

- [ ] Создать `tools/evaluate_predictions.py`. Вход: CSV `id,score` (дополнительные колонки допустимы), путь к датасету и режим: один проверяемый UTC-день либо оба дня OOF.
- [ ] Получить метки из `train.csv`, день из `train_frames.csv`; соединять по ID, не по порядку строк. Исключить `table` согласно policy и привести алиасы.
- [ ] Проверять полный ожидаемый набор ID выбранного режима, дубликаты, неизвестные ID, пропуски, NaN/inf и score вне [0,1]. Некорректный файл должен завершаться с понятным сообщением и ненулевым кодом.
- [ ] Считать `sklearn.metrics.average_precision_score` отдельно по дням, среднее дневных AP, худший день и разницу с baseline на тех же строках. Не подменять AP accuracy или средним AP классов.
- [ ] Добавить диагностику по классам: количество боксов, число ошибок и AP, где он осмыслен. Для группы без положительных меток явно отметить, что AP неинформативен.
- [ ] Сохранять машиночитаемый результат локально в `outputs/` и краткую агрегированную сводку эксперимента.
- [ ] Добавить инструкцию запуска и указать, что из одного CSV нельзя доказать отсутствие утечки: обучение на другом дне отдельно проверяется в коде модели.
- [ ] Проверить инвариантность к перестановке строк, обработку одинаковых score и отказ на некорректных ID/баллах.

## Критерии готовности

Любой новый файл ответов проверяется без правки кода оценки. На текущих OOF воспроизводятся значения с допуском 1e-6:

| Метод | 25 октября | 26 октября | Среднее |
|---|---:|---:|---:|
| baseline | 0.860737 | 0.764807 | 0.812772 |
| temporal_core_c1_blend | 0.892035 | 0.788315 | 0.840175 |

Для режима одного дня проверяется только этот день, для OOF — все 198 нестоловых train-детекций. В Git публикуются код и агрегаты; индивидуальные предсказания, сабмиты, изображения и токены остаются локально.

## Передача результата

Участник с моделью передаёт `id,score` и описание обучения по дням. Исполнитель возвращает сравнение методов. Для этой задачи новую модель обучать не требуется. Предлагаемая ветка: `codex/evaluation`.
