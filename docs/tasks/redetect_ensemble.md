# Задание: ансамбль вторых детекторов (нужна видеокарта)

Исполнитель: Семён. Ветка `feat/redetect-ensemble` — это `codex/redetect-strong` плюс поддержка ансамбля в `tools/redetect.py`. Шаг 1 — около 80 минут, шаг 2 — около 70 минут и только если шаг 1 прошёл критерий.

Вторая редакция: порядок шагов, критерий и имена файлов исправлены по замечаниям Семёна.

## Идея

Сейчас сигнал нового детектора резкий: похожий бокс есть — 0, нет — 1. Обучаем ещё две такие же модели с другим seed и голосуем:

| Сколько моделей из трёх не подтвердили бокс | Сигнал D |
|---:|---:|
| 0 | 0 |
| 1 | 1/3 |
| 2 | 2/3 |
| 3 | 1 |

Это голосование, координаты боксов не усредняются. Формула прежняя: `S = (1 − confidence + D) / 2`, затем `(S + V) / 2` с вето экспертов.

Чего ансамбль не исправит: если все три модели одинаково обрезают человека, голосование даст тот же ответ. Он убирает случайные промахи одной модели, а не систематические ошибки границ людей.

## Что мы знаем и чего не знаем

- Сильный детектор с вето дал Public **0.82471** против 0.70514 у одного вето. Локально прирост поверх вето был +0.025.
- Почему на Public прирост настолько больше — **не доказано**. Возможные причины: итоговая модель обучена на 84 кадрах вместо 42; train и Public отличаются составом примеров. Разделить их мы не можем.
- На test у заметной доли боксов IoU с новым детектором лежит в 0.5–0.7: 33% чашек, 24% кистей, 20% людей. Это **не доказывает** нестабильность: близость к порогу только делает её возможной. Сколько боксов на самом деле меняют ответ от модели к модели, покажет строка «Боксов, по которым участники расходятся» в выводе `eval`.

## Что изменилось в `tools/redetect.py`

- `--seed N` — seed обучения (раньше был зашит 0).
- `--member NAME` для `train` и `predict` — имя участника. Запуск и предсказания получают суффикс: `runs/all_s1`, `pred_all_s1.csv`. Участник `base` — уже обученные модели, их переобучать не надо.
- `--members base s1 s2` для `eval` и `submit` — собрать ансамбль.
- **Состав входит в имена результатов:** `oof_features_ens-base-s1-s2.csv`, `oof/redetect_strong_ens-base-s1-s2_veto.csv`, `submissions/redetect_strong_ens-base-s1-s2_veto.csv`. Ансамбли разного состава друг друга не затирают. Оценка одного участника `--members s1` пишет в файлы с суффиксом `_s1` и не трогает файлы `base`.
- `eval` для ансамбля сразу печатает строки «+ вето» для каждого участника и ансамбля, если посчитано `outputs/expert_veto/train_features.csv`. Решение принимается по ним.
- С одним участником `base` всё как раньше; на твоих файлах `eval --tag strong` даёт прежние 0.9147 / 0.8455, строка «base + вето» — 0.9076 / 0.8915.

Датасеты уже собраны в `outputs/redetect_strong/yolo/`, `build` повторять не нужно.

## Шаг 1. Проверка по дням (около 80 минут)

Четыре дневные модели: два новых seed на каждый день. Рецепт тот же, меняется только seed.

```
python tools/redetect.py train --tag strong --member s1 --seed 1 --weights weights/yolo11l.pt --epochs 250 --batch 4 --device 0
python tools/redetect.py predict --tag strong --member s1 --device 0
python tools/redetect.py train --tag strong --member s2 --seed 2 --weights weights/yolo11l.pt --epochs 250 --batch 4 --device 0
python tools/redetect.py predict --tag strong --member s2 --device 0
python tools/redetect.py eval --tag strong --members base s1 s2
```

Закоммитить `pred_day_*_s1.csv`, `pred_day_*_s2.csv`, `oof_features_ens-base-s1-s2.csv` и вывод `eval`.

### Критерий, заданный заранее

Сравниваем итоговое сочетание с вето, строка `ансамбль base+s1+s2 + вето`, с текущим решением `участник base + вето`: **0.9076 / 0.8915, среднее 0.8996**.

- **Успех:** среднее выше 0.8996 и ни один из двух дней не ниже текущего.
- **Провал:** иначе. Остаётся одиночная модель (Public 0.82471), шаг 2 не запускаем.

Сравнение со средним по участникам не используется: два слабых участника опустили бы планку.

Дополнительно записать в отчёт, не как критерий: AP каждого участника с вето (разброс между seed) и число боксов, по которым участники расходятся.

## Шаг 2. Итоговые модели и файл для test (около 70 минут) — только при успехе шага 1

```
python tools/redetect.py train --tag strong --member s1 --seed 1 --weights weights/yolo11l.pt --epochs 250 --batch 4 --device 0 --sets all
python tools/redetect.py predict --tag strong --member s1 --device 0 --sets all
python tools/redetect.py train --tag strong --member s2 --seed 2 --weights weights/yolo11l.pt --epochs 250 --batch 4 --device 0 --sets all
python tools/redetect.py predict --tag strong --member s2 --device 0 --sets all
python tools/redetect.py submit --tag strong --members base s1 s2
python tools/blend_veto.py test submissions/redetect_strong_ens-base-s1-s2_veto.csv
```

Результат: `submissions/redetect_strong_ens-base-s1-s2_veto_veto.csv`. Закоммитить `pred_all_s1.csv`, `pred_all_s2.csv`, `test_features_ens-base-s1-s2.csv`. Отправку в Kaggle согласовать.

Если важнее успеть использовать сегодняшние попытки Kaggle, шаги можно поменять местами. Это более рискованный порядок: час видеокарты уйдёт на вариант, который локально ещё не проверен.
