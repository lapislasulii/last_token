# Задание: смешать синтетику с вето и переобучить второй детектор как следует (нужна видеокарта)

Исполнитель: тимейт с RTX 5070 Ti. Часть A — 20 минут, часть B — около 2 часов. Предлагаемая ветка: `feat/redetect-strong`.

## Где мы сейчас

| Подход | AP 25.10 | AP 26.10 | Среднее | Public |
|---|---:|---:|---:|---:|
| baseline `1 − confidence` | 0.861 | 0.765 | 0.813 | 0.641 |
| CLIP с рамкой | 0.868 | 0.769 | 0.818 | 0.666 |
| синтетика + baseline 50/50 (3 seed) | 0.86–0.90 | 0.79–0.81 | 0.841 | — |
| **вето экспертов** (`reports/expert_veto.md`) | 0.886 | 0.864 | 0.875 | **0.705** |

На Public мы 16-е (0.705), у 7-го места 0.876, у первого 0.966. Двенадцать команд выше 0.77, скоры идут сплошной лестницей. Семейство «CLIP + логрег» упёрлось в ~0.84 локально, синтетика это подтвердила. Нужен подход другого порядка, и единственный кандидат по правилам — свой детектор, обученный на ручных боксах, с которым сверяются боксы исходного детектора.

Первая попытка (`reports/redetect_results.md`) провалилась, но она была заведомо слабой: `yolo11s`, 60 эпох, batch 2, всего 4 класса и 80–160 боксов на день. Здесь та же идея с нормальным рецептом.

## Часть A. Смешать синтетику с вето (20 минут, сделать первой)

Вето ловит ложные срабатывания, синтетика целится в геометрию, поэтому они могут сложиться. OOF-файлы синтетики есть только на твоей машине.

- [ ] Подтянуть `main` в свою ветку: там `tools/expert_veto.py` и `tools/blend_veto.py`.
- [ ] Скачать в `weights/` два файла (по ~115 МБ):
  - https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11x.pt
  - https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11x-pose.pt
- [ ] Посчитать вето для train и test (на карте это пара минут):

```
python tools/expert_veto.py train --det-device 0 --pose-device 0
python tools/expert_veto.py test --det-device 0 --pose-device 0
```

Сверка: на train должно выйти `expert veto AP by day [0.8855 0.8637]`, вето поднимает 44 бокса из 198; на test — 47 из 362.

- [ ] Смешать каждый из трёх seed и test-файл seed 43:

```
python tools/blend_veto.py train oof/synthetic_rankblend_seed42.csv
python tools/blend_veto.py train oof/synthetic_rankblend_seed43.csv
python tools/blend_veto.py train oof/synthetic_rankblend_seed44.csv
python tools/blend_veto.py test submissions/synthetic_rankblend_seed43.csv
```

Формула фиксирована: `(скор + veto) / 2`, вес не подбирается.

- [ ] Критерий: строка `input + veto` выше строки `baseline + veto` (0.8855 / 0.8637) на обоих днях хотя бы у двух seed из трёх. Если да — прислать `submissions/synthetic_rankblend_seed43_veto.csv`, отправим в Kaggle. Если нет — синтетика поверх вето ничего не добавляет, идём дальше без неё.

## Часть B. Второй детектор, сильный рецепт (около 2 часов)

`tools/redetect.py` уже доработан: ключ `--tag` кладёт всё в отдельную папку `outputs/redetect_<tag>`, ключ `--extra-classes` добавляет в обучение столы и «отвлекающие» ручные классы, команда `submit` собирает файл для test.

Что изменено относительно первой попытки и зачем:

| Было | Стало | Зачем |
|---|---|---|
| `yolo11s` | `yolo11l` (или `yolo11x`, если влезет в 12 ГБ) | точнее границы боксов |
| 60 эпох, batch 2 | 250 эпох, batch 4 | первая модель была недоучена: mAP50-95 ≈ 0.5 на своём же дне |
| 4 класса, 240 боксов | 12 классов, 1005 боксов | столы задают геометрию сцены; телефоны, тарелки и вещи учат не путать их с чашками и кистями |
| только эвристики согласия | заранее выбранное правило: нет пары с IoU ≥ 0.6 → бокс вверх очереди | повторяет определение метки `error` |

Сцена статична, камера одна, поэтому переобучение детектора на эту сцену здесь полезно, а не вредно.

### Шаги

- [ ] Собрать датасеты и обучить два «дневных» детектора:

```
python tools/redetect.py build --tag strong --extra-classes
python tools/redetect.py train --tag strong --weights yolo11l.pt --epochs 250 --batch 4 --device 0
```

Если не хватает памяти — `--batch 2`. Ожидаемое время: 15–30 минут на каждый день.

- [ ] Прогнать каждый детектор по кадрам другого дня и посчитать метрики:

```
python tools/redetect.py predict --tag strong --device 0
python tools/redetect.py eval --tag strong
```

- [ ] Смотреть три вещи в выводе `eval`:
  1. строка `veto: (base + [iou_same<0.6]) / 2` — основной вариант, выбран заранее;
  2. блок «AP по классам», строка `person`: было `base=0.645 ours=0.405`;
  3. файл `oof/redetect_strong_veto.csv` — проверить `python tools/evaluate_predictions.py score oof/redetect_strong_veto.csv --mode oof --name redetect_strong`.

- [ ] Посмотреть глазами 10–15 кадров отложенного дня с боксами нового детектора: рисует ли он сидящих за столом целиком, как разметчик. Это важнее цифр mAP.

### Критерии

**Успех:** основной вариант даёт среднее не ниже 0.86 и оба дня выше baseline (0.861 / 0.765). Ориентир — вето экспертов, 0.875.

**Бросаем:** `person ours` снова ниже `base` (0.645) и основной вариант ниже baseline хотя бы на одном дне. Разрешена одна повторная попытка с другим размером модели (`yolo11m.pt` или `yolo11x.pt --batch 2`), больше ничего не перебирать.

### Если успех

```
python tools/redetect.py predict --tag strong --device 0 --sets all

```

- [ ] Сложить с вето экспертов (оно ловит то, что детектор на 84 кадрах может не выучить):

## Часть C. Необязательно, только если карта простаивает

Одна попытка синтетики с другим кропом для `person`: продлить кроп вниз на высоту бокса (сейчас запас 25% со всех сторон). Причина: когда детектор обрезает сидящего по столу, разметчик в 13 случаях из 22 рисовал бокс до пола, а в 9 — тоже только верх тела, и зависит это, судя по кадрам, от того, видны ли ноги под столом. В текущий кроп эта область не попадает. Критерий тот же, что в `docs/tasks/synthetic_boxes.md`; параметры искажений не трогать.

## Правила

- Обучать детектор только на ручных боксах train. Размечать test руками запрещено.
- Проверка по дням: детектор, обученный на одном дне, оценивает другой. Детектор `all` используется только для test.
- Число эпох и размер модели выбираются до просмотра метрик отложенного дня; эпоху по отложенному дню не выбирать (`val=False` в скрипте уже стоит).
- Веса только публичные, ссылки идут в отчёт: https://github.com/ultralytics/assets/releases/tag/v8.3.0
