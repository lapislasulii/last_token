# Задание 3: разобрать ошибки и предложить признаки

## Идея

Понять, какие ошибки пропускают baseline и уже обученная временная модель, затем превратить наблюдения в 2–3 проверяемые гипотезы. Цель — улучшить порядок проверки боксов оператором.

«Отфильтровать ошибки» означает выбрать их для исследования, а не удалить неудобные строки или изменить официальные метки.

## Что уже есть

- `python tools/view_frame.py` открывает локальный просмотрщик: ручные/машинные боксы, confidence, error, соседи, фильтры.
- `python tools/train_temporal.py` создаёт `oof/baseline.csv` и `oof/temporal_core_c1_blend.csv`.
- `reports/data_overview.md`: 198 нестоловых боксов, 109 ошибок; преобладают геометрические ошибки и ложные срабатывания. Разделение по причинам в отчёте эвристическое.
- Простой большой набор геометрических признаков уже не помог. Повторять его без новой гипотезы не нужно.

## Что именно сделать

- [ ] Соединить train с OOF-ответами обоих методов по `id`. Для анализа использовать OOF, а не ответы финальной модели на её обучающих примерах.
- [ ] Выбрать до 10 доступных примеров в каждой группе, с охватом обоих дней и разных классов: ошибочные боксы с низким score, правильные с высоким score, случаи, где временная модель ухудшила порядок относительно baseline. Пересечения групп разрешены; это небольшой целевой разбор, не ручная разметка всего датасета.
- [ ] В просмотрщике сравнить машинный и ручной бокс, затем соседние кадры. Проверить правила разметки person, чашек и кистей. Существующие `error` не менять.
- [ ] Составить короткий отчёт: наблюдение → пример → предполагаемый вычисляемый признак → почему доступен на test. Детальные ID и кадры хранить локально в `outputs/error_analysis/`; в Git публиковать агрегаты, описание гипотез и код без изображений.
- [ ] Выбрать максимум 2–3 гипотезы. Например: положение человека относительно стола, изменение геометрии по времени, более надёжное сопоставление соседних боксов вместо независимого максимального IoU.
- [ ] Реализовать одну наиболее обоснованную гипотезу в отдельном модуле/скрипте. Выход: `id,feature_1,feature_2,...`, одна строка на детекцию; одинаковые названия и смысл признаков на train/test. Обрабатывать отсутствующий контекст и реальные интервалы времени.
- [ ] Передать признаки участнику с моделью для отдельного эксперимента: текущий вариант → тот же вариант плюс новая группа признаков. Результат проверяется общей оценкой участника №1.

## Критерии готовности

Есть короткий отчёт с приоритетом гипотез и хотя бы одна воспроизводимая таблица новых признаков. ID уникальны, строки не потеряны, нет зависимости от `error`, ручных боксов test или других недоступных при предсказании данных. Подтверждённое отсутствие прироста тоже считается полезным результатом.

Ручные боксы train используются для понимания ошибки. Их IoU нельзя просто передать модели как признак: на test ручных боксов нет. Ручная разметка test и подстановка ответов запрещены.

## Передача результата

Исполнитель передаёт код признаков и их описание участнику с моделью; участник №1 возвращает метрики. Если признак обучает статистику, например типичные размеры из machine pool, нужен отдельный fit на обучающем дне и transform на отложенном. Заранее объединять статистику обоих дней нельзя. Предлагаемая ветка: `codex/error-analysis`.
