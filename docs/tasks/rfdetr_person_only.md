# Задание: голос RF-DETR только у людей

Исполнитель: Codex на машине Семёна. Ветка `codex/redetect-strong`. Время: около часа, только CPU, без обучения.
Отправок в Kaggle не делать — отправляет команда. Существующие файлы в `outputs/`, `oof/`, `submissions/` не
перезаписывать. Продолжение `docs/tasks/rfdetr_judge.md`: обозначения и ворота оттуда.

## Что случилось и почему этот вариант

Основной вариант прошлого задания (`D = (Y + R)/2` для всех классов, RF-DETR 1120) локально дал 0.94658 / 0.92671
против опорных 0.92579 / 0.92565, а на Public — **0.90664 против 0.92465**.

Ошибки в коде RF-DETR нет. На test он соглашается с большинством YOLO в 77–86% боксов по каждому классу (кроме подносов,
54%), смещения id классов нет. Проблема в том, где голос RF-DETR применяется. Предварительный подсчёт (5 голосов YOLO из 6,
`base` не учтён; train — оба отложенных дня вместе):

| Класс | Клетка | train: боксов / ошибок | test: боксов (кадров) |
|---|---|---|---|
| люди | большинство YOLO против, RF-DETR за | 20 / 7 | 19 (15) |
| люди | YOLO за, RF-DETR против | 11 / 6 | 3 (3) |
| чашки, руки, подносы | большинство YOLO против, RF-DETR за | **22 / 18** | **45 (31)** |
| чашки, руки, подносы | YOLO за, RF-DETR против | 10 / 6 | 8 (5) |

У людей RF-DETR чаще исправляет YOLO, чем портит (19 против 12). Ворота 2 проверяли только людей, поэтому их прошли.
У остальных классов он почти всегда «принимает» бокс, который на самом деле ошибка: исправил 10, испортил 22. На test
таких боксов 45, и основной вариант опускал каждый из них вниз очереди. Это объясняет провал на Public лучше, чем шум.

**Честная оговорка.** Этот вариант придуман после того, как мы увидели Public. Доверять ему меньше, чем вариантам,
зафиксированным заранее. Поэтому — ровно один вариант, без перебора.

## Вариант (единственный)

`Y`, `R`, `P`, `V`, `L` — как в `rfdetr_judge.md`. `R` — только RF-DETR 1120, обычный прогон
(`pred_day_*_rfdetr1120.csv`, `pred_all_rfdetr1120.csv`).

| Класс | Доля голосов D' |
|---|---|
| `person`, вне окна (центр x ≥ 330) | `(6·D + P) / 7`, где `D = (Y + R) / 2` |
| `person`, у окна | `D = (Y + R) / 2` |
| `nude_hands`, `cup`, `tray` | `Y` — как в опорном варианте, RF-DETR не участвует |

Скор: `(1 − confidence + D' + 2·max(V, L)) / 4`, как раньше.

## Шаги

1. **Повторить таблицу выше с шестью голосами YOLO** (с `base`) на обоих отложенных днях и на test. Записать в отчёт
   рядом с моими числами. Если с `base` картина другая (у остальных классов RF-DETR не хуже YOLO), остановиться и
   написать об этом — тогда объяснение неверное, и этот вариант не нужен.
2. **Ворота 0:** опорный вариант снова даёт 0.92579 / 0.92565, основной вариант прошлого задания — 0.94658 / 0.92671.
   Расхождение — ошибка в скрипте.
3. **Ворота 3 для нового варианта** против опорного, по каждому дню:
   - ни один день не хуже опорного больше чем на 0.005;
   - среднее двух дней выше опорного минимум на 0.003;
   - при исключении любого одного из 35 кадров среднее остаётся выше опорного;
   - парный bootstrap по кадрам, 3000 повторов: доля повторов с приростом — в отчёт.
   Отдельно AP только по людям каждого дня: опорный против нового.
4. **Если ворота 3 пройдены** — собрать test:
   `submissions/redetect_rfdetr1120_personR_pvote_nowin_legs_veto.csv`. Проверить
   `python tools/submission_auditor.py <новый файл> --vs <файл с Public 0.92465>`. В отчёт: сколько строк сдвинулось
   (должны меняться только `person`; если сдвинулся другой класс — ошибка), сколько людей поднялось и опустилось
   больше чем на 10 мест.
5. Если ворота 3 не пройдены — файл для test не собирать. Это нормальный результат.
