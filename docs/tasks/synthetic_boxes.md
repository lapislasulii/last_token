# Задание: синтетические примеры из ручных боксов (нужна видеокарта)

Исполнитель: тимейт с RTX 5070 Ti. Срок: 2–3 часа. Предлагаемая ветка: `feat/synthetic-boxes`.

## Идея в двух абзацах

Сейчас все визуальные модели учатся на 198 размеченных детекциях, и этого мало: все варианты (локально 0.81–0.84) неотличимы от baseline при разбросе ±0.04–0.05. Но в `human_boxes_train.csv` лежат 1032 ручных бокса, и метка `error` определена через них: бокс верный, если IoU с ручным боксом того же класса ≥ 0.6.

Значит, обучающие примеры можно делать самим. Берём ручной бокс, искажаем его (сдвигаем, растягиваем, обрезаем) и считаем IoU искажённого бокса с исходным. Если IoU < 0.6 — это пример ошибки, иначе пример верного бокса. Так из 1032 боксов получаются тысячи примеров с точной меткой, и тот же пайплайн «CLIP с рамкой» учится на них отличать хорошо посаженный бокс от плохо посаженного.

## Что известно из разбора train

Ручных боксов оцениваемых классов: `person` 82, `nude_hand` 70 + `nude_hands` 13 (это один класс, алиас из `scoring_policy.json`), `cup` 50, `tray` 25.

Ошибки геометрии у `person` (23 из 32 ошибок класса) делятся на два стереотипных режима. Числа — отклонение бокса детектора от ручного в долях размера ручного бокса:

| Режим | Сколько | Как выглядит |
|---|---:|---|
| Низ обрезан по столу | 13 | верх и бока совпадают, низ выше ручного на 27–59% высоты; площадь 0.3–0.8 от ручной |
| Бокс слишком большой | 6 | площадь в 1.5–2.2 раза больше ручной, обычно растянут вниз или в одну сторону |
| Прочее | 4 | сдвиг вбок, обрезан верх |

Ложные срабатывания `cup` и `nude_hands` чаще всего стоят на объектах других ручных классов:

| Класс детекции | На чём стоит на самом деле (ручной класс) |
|---|---|
| `cup` | `empty_plate`, `phone`, `personal_items`, `nude_hands`, `carton` |
| `nude_hands` | `phone`, `cup`, `bottle`, `bracelet`, край `uniform_not_ok` |
| `tray` | `empty_plate`, `phone` |
| `person` | вещи на стуле (`personal_items`), пустое место у стола |

## Что именно сделать

### 1. Генератор примеров

- [ ] Создать `tools/train_synthetic_boxes.py`. За основу взять `tools/train_marked_context.py`: кроп, рамка, энкодер там уже написаны.
- [ ] Читать `human_boxes_train.csv`. Координаты нормированы (`cx, cy, w, h`), перевести в пиксели умножением на 1280 и 720. Привести `nude_hand` → `nude_hands`.
- [ ] Для каждого ручного бокса классов `person`, `nude_hands`, `cup`, `tray` сгенерировать 30 искажённых копий с фиксированным seed. Каждая копия — строка `(frame_id, class_name, x1, y1, x2, y2, error)`, где `error = 1`, если IoU копии с исходным боксом < 0.6. Боксы обрезать по границам кадра.

Виды искажений:

| Вид | Для кого | Как делать | Доля копий |
|---|---|---|---:|
| Малый шум | все классы | сдвиг каждой стороны на ±0–8% размера | 30% |
| Большой шум | все классы | сдвиг центра на ±5–25% размера, масштаб сторон 0.7–1.4 независимо | 40% |
| Обрезан низ | только `person` | `y2 = y1 + h × U(0.40, 0.80)`, бока ±5% | 15% (у остальных классов отдать большому шуму) |
| Слишком большой | только `person` | растянуть вниз или в одну сторону так, чтобы площадь выросла в 1.4–2.3 раза | 15% (аналогично) |

- [ ] Добавить ложные срабатывания: ручные боксы чужих классов из таблицы выше, с меткой `error = 1` и классом детекции из левой колонки. Каждому — 5 копий с малым шумом. Для `person` взять боксы `personal_items` размером не меньше 60×60 пикселей.
- [ ] Проверить баланс: доля `error = 1` в каждом классе должна быть 40–60%. Если нет — поменять доли видов искажений, а не порог IoU.
- [ ] Сохранить 20 случайных примеров каждого класса картинкой-листом (кроп с рамкой, подпись — IoU и метка) и посмотреть глазами: рамки должны быть похожи на настоящие ошибки детектора из `reports/sheet_train_most_errors.jpg`.

### 2. Модель

- [ ] Эмбеддинги: тот же кроп 1.5× с красной рамкой, 224×224, CLIP ViT-L/14 (`openai/clip-vit-large-patch14`, ревизия уже зафиксирована в `train_marked_context.py`). На 5070 Ti ставить `--batch-size 64`. Примеров выйдет около 8–9 тысяч, это несколько минут.
- [ ] Эмбеддинги настоящих детекций train и test `train_marked_context.py --encoder clip` сохраняет в `outputs/marked_context_clip/features.npz` и `test_features.npz` (папка не в Git). Если они остались на твоей машине и кроп с рамкой делаются тем же кодом — пересчитывать не надо, иначе пересчитать, это минута.
- [ ] Голова: StandardScaler → PCA 64 → логистическая регрессия с L2 (`C = 1`). К признакам добавить one-hot класса. Обучать **без offset по confidence**: у синтетики его нет.
- [ ] Итоговый скор для настоящих детекций: rank-average визуального скора и `1 − confidence`, вес **фиксированный 50/50**. Вес на 198 строках не подбирать: проверено, что логрег с новым признаком поверх confidence на таком объёме переобучается (0.806 против 0.813 у baseline).

### 3. Честная проверка по дням

- [ ] Для оценки на 26.10: синтетика только из ручных боксов кадров 25.10; scaler, PCA и логрег тоже обучены только на ней. Для оценки на 25.10 — наоборот.
- [ ] Оценивать на настоящих детекциях отложенного дня (198 строк суммарно), через `tools/evaluate_predictions.py`. Формат OOF-файла — `id,score`.

| baseline `1 − confidence` | 0.861 | 0.765 | 0.813 |
| только визуальный скор (синтетика) | | | |

- [ ] Отдельно посчитать AUC визуального скора внутри каждого класса и сравнить с AUC confidence: `person` 0.744, `nude_hands` 0.708, `cup` 0.794, `tray` 0.738. Главная цель — `person` и `nude_hands`, это 78% строк test.
- [ ] Если прирост есть — проверить устойчивость: 3 разных seed генератора, разброс среднего AP.

### 4. Необязательное, только если основной вариант дал прирост

- [ ] Добавить в обучение настоящие детекции обучающего дня с весом ×10 и посмотреть, стало ли лучше.
- [ ] Заменить CLIP с рамкой на inside/outside (`tools/train_clip_spatial.py`).

## Критерии

**Успех:** rank-average 50/50 даёт среднее не ниже 0.843 (+0.03 к baseline) и не падает ни на одном из дней относительно baseline.

**Бросаем:** прирост меньше +0.03 или падение на любом дне после одной попытки поправить генератор (посмотрев лист примеров). Не перебирать параметры искажений больше двух раз: на 198 строках это превращается в подгонку.

## Что вернуть

1. Таблицу из раздела 3 и AUC по классам — в `reports/synthetic_boxes.md`.
2. OOF-файл `id,score` и, если критерий успеха выполнен, файл предсказаний для test (обучение на синтетике обоих дней). В Kaggle не отправлять без согласования: отправок осталось мало.
3. Код в ветке. Индивидуальные предсказания, эмбеддинги и картинки в Git не класть, как и раньше.

## Правила, которые нельзя нарушить

- Синтетику делать только из кадров train. Ручных боксов test у нас нет, и размечать test руками запрещено.
- Ничего не подбирать по Public leaderboard.
- Веса только публичные: CLIP ViT-L/14 с Hugging Face, ссылка и ревизия идут в отчёт.
