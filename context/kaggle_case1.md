# Kaggle: rascar-hack-case-1 (аудит детектора)

Источник: https://www.kaggle.com/competitions/rascar-hack-case-1 (скопировано со страницы 2026-11-11)

## Overview

Камера в обеденном зале кафе каждые 30 секунд отправляет кадр, детектор превращает его в боксы: люди, руки, чашки, подносы. Детектор ошибается, а оператор не успевает проверить каждую детекцию.
Постройте ранжирование, которое поднимает ошибочные боксы в начало очереди проверки. Для каждой детекции тестовых кадров нужно выдать `score` от 0 до 1: чем выше, тем вероятнее, что детекция ошибочная. Метрика — Average Precision.

## Description

Детектор ошибается: принимает предмет на стуле за человека, обрезает сидящих по краю стола, ставит два бокса на один объект, путает класс. Оператор не успевает проверить каждую детекцию.

Данные реальные, их предоставила компания КИРА. Это кадры камеры 5 из обеденного зала, лица на изображениях размыты.

- Train: 84 кадра за 25–26 октября 2026 года, у каждой детекции есть метка `error`.
- Test: 128 кадров за 27–28 октября 2026 года, метки скрыты. Оценивается часть строк, ответ нужен для всех.
- Контекст: у каждого целевого кадра есть соседние кадры за 30 секунд до и после, вместе с детекциями на них.
- Машинный пул: 5 388 кадров за 25–26 октября с предсказаниями того же детектора, без ручной разметки.

### Что считается ошибкой

Оцениваются классы из `scoring_policy.json`, алиасы приводятся к одному имени: `nude_hand` → `nude_hands`, `white_napkin` → `napkin`.
На каждом кадре предсказанные и ручные боксы одного класса сопоставляются один к одному, если их IoU не ниже 0,6. Сначала максимизируется число пар, затем суммарный IoU.

- Предсказание, которое сопоставилось с ручным боксом, получает `error = 0`.
- Все остальные предсказания получают `error = 1`. Это дубли, ложные срабатывания, ошибки класса и ошибки геометрии.
- Объекты, на которые детектор не поставил ни одного бокса, в оценку не входят.

Детекции класса `table` в test не оцениваются: на столах детектор почти не ошибается (3 ошибки на 472 стола в train). В train и в файлах контекста столы оставлены.

### Как размечали

- `person` — бокс охватывает всего человека, включая части тела, закрытые столом, например ноги под столом. Детекция, которая обрезает сидящего по краю стола, часто получает IoU ниже 0,6 и считается ошибкой геометрии.
- `nude_hands` — любые видимые голые кисти рук, в том числе руки гостей.
- `cup` — чашки и стаканы, включая стаканы навынос. Бутылки размечены отдельным классом `bottle`.

Организаторы вручную проверили ошибочные детекции классов `nude_hands` и `cup`, рядом с которыми нет ручного бокса того же класса. Кисти и чашки, которые разметчик пропустил, добавлены в разметку (`source = revision`), после чего метки пересчитаны.

### Сроки

- 11 ноября 2026, 13:00 МСК — старт соревнования.
- 14 ноября 2026, 23:59 МСК — финальный сабмит и выбор двух отправок для финала. После этого отправки не принимаются.
- 15 ноября 2026 — защиты финалистов и награждение.

### Призы

На весь хакатон три призовых места, независимо от кейса: 1 место — 100 000 ₽, 2 место — 65 000 ₽, 3 место — 35 000 ₽.

В финал проходят 5–7 лучших команд каждого кейса по Private leaderboard. Сколько именно, зависит от отрыва на Private. На защите жюри выбирает три команды с самыми сильными решениями из обоих кейсов. Метрики кейсов нормированы, чтобы сравнение между ними было честным.

## Evaluation

Метрика — Average Precision по бинарной метке `error`, где 1 означает ошибочный бокс. Считается через `sklearn.metrics.average_precision_score`, одинаковые значения `score` обрабатываются так же, как в sklearn.

Тестовые кадры разделены на непересекающиеся части. Public leaderboard виден во время соревнования. По Private leaderboard отбираются финалисты. Одна отправка покрывает обе части.
Оценивается часть тестовых строк; какие — не сообщается, поэтому ответ нужен для всех строк. Организаторы дополняют разметку Private кадрами из этого же test. Итоговый Private с дополненной разметкой считают после финального сабмита тем же кодом метрики для выбранных финальных отправок всех команд.

### Формат отправки

`submission.csv` с колонками `id,score`. Каждый `id` из `sample_submission.csv` ровно один раз, `score` — конечное число от 0 до 1, порядок строк не важен.

Бейзлайн — `baseline.ipynb`: сортировка по `1 − confidence`, проверка на днях train, сохранение `submission.csv`.
До 10 отправок в день. Для финала можно выбрать 2 отправки.

## Dataset Description

Время в таблицах и в именах кадров — UTC. Размер кадра 1280×720. Типичный интервал 30 секунд, но бывают пропуски.
`id` и `detection_id` — случайные идентификаторы, для одной детекции совпадают во всех файлах; о порядке, классе или времени ничего не говорят.
Координаты боксов `x1, y1, x2, y2` в таблицах предсказаний — в пикселях.

| Файл | Что внутри |
|---|---|
| TASK.txt | полное условие задачи |
| train.csv | детекции на целевых кадрах train и метка error: id, frame_id, class_name, confidence, x1, y1, x2, y2, error |
| test.csv | детекции на целевых кадрах test без error; детекций table нет |
| sample_submission.csv | формат ответа: id, score |
| train_frames.csv, test_frames.csv | кадры: frame_id, время, путь к изображению, размеры |
| train_context.csv, test_context.csv | целевой кадр и соседи: frame_id, previous, next |
| train_stream_predictions.csv, test_stream_predictions.csv | детекции на всех кадрах части, включая соседние без разметки: detection_id, frame_id, class_name, confidence, x1, y1, x2, y2 |
| human_boxes_train.csv | ручные боксы train в нормированных cx, cy, w, h; evaluated_class — входит ли класс в оценку; source = revision / annotator |
| scoring_policy.json | классы в оценке, алиасы, порог IoU |
| <frame_id>.jpg | изображения (целевые, соседние, пул) в одной папке; путь — колонка image_path |
| baseline.ipynb | бейзлайн 1 − confidence и пример локальной валидации |
| MACHINE_POOL.txt | описание машинного пула |
| machine_frames.csv, machine_predictions.csv | пул: 5 388 кадров и предсказания детектора |

### Машинный пул

Кадры камеры 5 за 25–26 октября 2026. `machine_frames.csv` связывает frame_id с изображением и временем, `machine_predictions.csv` — предсказания того же детектора (автоматические, с ошибками и пропусками).
Изображения пула уменьшены до 640×360; координаты в `machine_predictions.csv` — в пикселях исходного 1280×720 (для наложения делить на 2). Ручной разметки и error нет.
Применение: псевдоразметка, обучение представлений, моделирование зон, проверка устойчивости детекций во времени. Учитывать фактические интервалы. Для честной проверки по дню держать этот день пула вне обучения.

### Локальная валидация

Делить train по UTC-дням: подбирать параметры на одном дне, проверять на другом. Класс table при проверке исключать. Если используется пул — держать день валидации и его контекст вне обучения.
