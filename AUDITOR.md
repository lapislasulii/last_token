# Аудитор сабмитов

Проверяет файл `id,score` основной системы **до отправки на Kaggle**. Отвечает на два вопроса:

1. Примет ли Kaggle этот файл?
2. Не сломалась ли очередь по дороге (перепутанный смысл, сдвиг строк, копия baseline)?

Аудитор подключается сбоку: код основной системы не меняется, признаки берутся из `tools/train_logreg.py` и `tools/temporal_features.py`. Новых зависимостей нет, нужны только pandas, numpy и scikit-learn.

## Запуск

```bash
python audit_demo.py                                   # демо: сабмиты из submissions/ + типичные баги
python tools/submission_auditor.py path/to/my.csv      # проверить свой файл (код выхода 1 при error)
python tools/submission_auditor.py new.csv --vs best.csv   # + сравнить очередь с лучшим сабмитом
python -m unittest discover -s tests -p test_submission_auditor.py -v
```

Нужен локальный датасет в `data/rascar-hack-case-1/`. Отчёты сохраняются в `outputs/audit/` (HTML с превью кадров и JSON). Этот каталог в `.gitignore`: в HTML есть кадры под NDA, поэтому в Git его не добавляем.

## Что проверяется

| Уровень | Правило | Что ловит |
|---|---|---|
| error | `columns`, `row_count`, `missing_id`, `extra_id`, `duplicate_id` | файл не совпадает с шаблоном из 362 ID |
| error | `not_finite`, `out_of_range` | NaN, текст, баллы вне [0, 1] |
| error | `constant` | все баллы одинаковые: модель упала, подставилось значение по умолчанию |
| warning | `few_unique` | слишком много ничьих в очереди |
| warning | `inverted` | очередь направлена против второго мнения: score значит «бокс верный», а не «проверить первым» |
| warning | `unrelated` | очередь почти не связана со вторым мнением; типичная причина — баллы сдвинуты относительно id при merge |
| warning | `same_as_baseline` | порядок совпадает с `1-confidence`: модель ничего не добавила |
| warning | `disagreement` | сильных расхождений со вторым мнением больше 5% |
| warning | `class_pushed_down` | целый класс (≥ 10 боксов) выпал из начала очереди: у системы в топ-20% меньше трети той доли, что у мини-модели (например, баг фильтра обнулил чашки) |
| info | `missed`, `overflagged` | конкретные боксы, где система и мини-модель расходятся сильнее всего, с объяснением причины и превью кадра |

Итоговый вердикт: `error`, если есть хоть одна ошибка; иначе `warning`, если есть предупреждение; иначе `ok`.

Для каждого сабмита печатается **разбивка по классам**: какая доля боксов класса попала в первые 20% очереди у системы и у мини-модели и сколько сильных расхождений приходится на класс.

## Сравнение двух сабмитов (`--vs`)

Помогает выбрать два финальных сабмита. Для нового файла относительно опорного (например, лучшего на Public) показываются:

- ранговая корреляция Spearman, общий топ-20%, сколько боксов вошло в топ и вышло из него, медианный сдвиг;
- какая из двух очередей лучше согласуется с мини-моделью;
- по классам: доля в топ-20% и средний сдвиг (+ = ближе к началу очереди);
- боксы, сильнее всего поднявшиеся и опустившиеся, с объяснением и превью кадра;
- вывод: «почти одинаковые (Spearman > 0.98) — пара почти не страхует от ошибки выбора», «сильно различаются (< 0.6) — разнообразная пара» или промежуточный вариант; отдельно указывается класс, сдвинувшийся сильнее всего.

Сравнение не говорит, какая очередь лучше: это решает Public AP. Оно показывает, *чем* они отличаются.

## Второе мнение: мини-модель

Логистическая регрессия на 5 числах, тот же набор, что у `temporal_core_c1`: confidence, лучший и худший IoU с соседними кадрами, разница confidence с соседями, IoU с дублем на текущем кадре. Обучается при запуске за пару секунд, поэтому не зависит от версии sklearn, в которой сохранены артефакты.

Проверка «учимся на одном дне, проверяемся на другом» на train:

| День | AP мини-модели | AP baseline `1-confidence` |
|---|---:|---:|
| 2026-10-25 | 0.894 | 0.861 |
| 2026-10-26 | 0.766 | 0.765 |

В топ-20% мини-модели ошибочны 85% боксов (в среднем по train 55%, в её спокойных 20% — 26%). Сама она не лучше основной системы на Kaggle. Её задача — служить независимой точкой отсчёта и ловить грубые поломки очереди, а не заменять модель.

Если мини-модель обучить не удаётся (или запуск с `--heuristics-only`), аудитор переходит на запасной балл: `1-confidence` плюс штраф за каждую сработавшую эвристику. Эвристики объясняют подозрения словами: дубль на кадре, низкий confidence, нет опоры во времени, низкий бокс человека, бокс у края кадра, крошечный бокс. В HTML-отчёте для каждой эвристики показано, как часто она указывает на настоящую ошибку в train.

| `logreg_class`, `logreg_geometry` | ok | формат верный, очередь согласуется со вторым мнением |
| `logreg_baseline`, `logreg_confidence` | warning | очередь совпадает с `1-confidence` — отправлять их нет смысла |
| корректная смесь | ok | |
| сдвиг строк при merge | warning | формат проходит, но Spearman падает до +0.07 |

| константа | error | очередь не упорядочена |

## Ограничения

- Аудитор не знает настоящих ответов теста. `ok` означает «файл корректен и очередь правдоподобна», а не «AP будет высоким».
- Хорошая модель может законно расходиться с мини-моделью: визуальные модели видят то, чего нет в 5 числах. Поэтому отдельные расхождения имеют уровень info, а warning выставляется только при массовых расхождениях.
- Пороги (5%, Spearman 0.3 и 0.995, топ/низ 10%) выбраны вручную по сабмитам команды, а не подобраны на метрике.
- Мини-модель обучена на тех же 198 боксах, которые использовались при выборе `temporal_core_c1`, поэтому её AP на отложенном дне может быть немного завышен.
- Превью кадров в HTML открываются, только если датасет лежит по стандартному пути.
