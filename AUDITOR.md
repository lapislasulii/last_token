# Аудитор сабмитов

Проверяет файл `id,score` основной системы **до отправки на Kaggle** и объясняет очередь оператору. Отвечает на четыре вопроса:

1. Примет ли Kaggle этот файл?
2. **Что это за файл?** Тот ли это сабмит, который дал лучший Public, или его старая или чужая версия?
3. Не сломалась ли очередь по дороге: перепутанный смысл, сдвиг строк, выпавший класс?
4. **Почему** бокс стоит в начале очереди? Ответ словами и с превью кадра.

Аудитор подключается сбоку: код основной системы не меняется. Признаки берутся из `tools/train_logreg.py`, `tools/temporal_features.py` и `tools/redetect.py`, предсказания детекторов — из `outputs/redetect_strong/` (лежат в git). Новых зависимостей нет: pandas, numpy, scikit-learn, scipy.

## Запуск

```bash
python audit_demo.py                                    # демо одной командой
python tools/submission_auditor.py path/to/my.csv       # проверить свой файл (код выхода 1 при error)
python tools/submission_auditor.py new.csv --vs best.csv    # + сравнить очередь с опорным сабмитом
python tools/tie_break.py submissions/leader.csv        # разбить ничьи в сабмите (новый файл *_tiebreak.csv)
python tools/tie_break.py --oof                         # эффект разбивки на отложенных днях
python tools/compare_oof.py oof/new.csv oof/ref.csv --min-gain 0.003 --max-day-drop 0.005   # критерий эксперимента
python -m unittest discover -s tests -p "test_*.py" -v
```

Три инструмента: **аудитор** проверяет сабмит перед отправкой, **разбивка ничьих** даёт кандидата на улучшение без обучения, **сравнение OOF** проверяет заранее заданный критерий любого эксперимента.

Нужен локальный датасет в `data/rascar-hack-case-1/`, хватит CSV; изображения нужны только для превью. По умолчанию опорным для `--vs` берётся лучший известный файл из `submissions/`, найденный по SHA256 или по имени файла лидера. Отчёты сохраняются в `outputs/audit/` (HTML и JSON). Этот каталог в `.gitignore`, потому что в HTML кадры под NDA.

## 1. Формат (error)

`columns`, `row_count`, `missing_id`, `extra_id`, `duplicate_id`, `not_finite`, `out_of_range`, `constant`. Каждое нарушение указывает на конкретный `id`. Слишком много одинаковых баллов даёт warning `few_unique`.

## 2. Опознание файла

- **По SHA256.** Реестр отправок, хеши которых записаны в `reports/`: 0.89753 (ансамбль + вето, любое совпадение), 0.89118 (с учеником), 0.80732 (ученик), 0.82471 (одиночный YOLO11l + вето; записан только префикс хеша).
- **По формуле.** Аудитор сам восстанавливает из закоммиченных предсказаний пять рецептов: baseline, одиночный YOLO11l и ансамбль base+s1+s2, каждый с «любым совпадением» и с сопоставлением «один к одному», и проверяет, воспроизводит ли файл один из них с точностью 5·10⁻⁶.
- **Вето без файлов вето.** Если `score = (S + V)/2`, то `2·score − S` даёт ровно 0 или 1. Так аудитор узнаёт, что в файле есть вето экспертов, и на каких боксах оно сработало. Признаков вето в git нет, они восстанавливаются из самого сабмита.
- **Предупреждение `not_best`.** Если у опознанного файла Public ниже лучшего известного (сейчас 0.90211, ансамбль один к одному + вето), это пример «отправили не тот файл».

Проверка на воспроизведённых рецептах: все 10 вариантов (5 рецептов, с вето и без) опознаются правильно. Ансамбль «один к одному» и «любое совпадение» отличаются ровно в 8 строках, как в `reports/one_to_one.md`. Это независимое подтверждение, что D ансамбля восстановлен верно.

## 3. Второе мнение: мини-модель

Логистическая регрессия на 7 признаках: confidence; согласие сильного детектора (`iou_same`, `match_conf`, нет пары «один к одному»); лучший и худший IoU с соседними кадрами; IoU с дублем на кадре. На train признаки детектора берутся у моделей, не видевших этот день, на test — у итоговой модели `base`.

| День (обучение на другом) | AP мини-модели | AP baseline |
|---|---:|---:|
| 2026-10-25 | 0.912 | 0.861 |
| 2026-10-26 | 0.856 | 0.765 |

В топ-20% мини-модели ошибочны 92% боксов (в среднем по train 55%). На людях AP 0.687 против 0.645 у baseline. Мини-модель не заменяет основную систему: у неё нет вето и двух других детекторов ансамбля. Она служит независимой точкой отсчёта.

**Осторожно: эти AP, вероятно, завышены.** Признаки детектора на train получены моделями, обученными на другом дне, а мини-модель учится на тех же двух fold. Об этой косвенной утечке команда предупреждает в `reports/clip_redetect_blend.md`. Без признаков детектора, только на временных признаках, мини-модель даёт 0.894 / 0.766. Аудитор показывает это рядом в отчёте. Мини-модель используется только для предупреждений и объяснений. Разбивка ничьих её не использует.

| Уровень | Правило | Что ловит |
|---|---|---|
| warning | `inverted` | очередь направлена против второго мнения (Spearman < −0.3) |
| warning | `unrelated` | очередь не связана со вторым мнением (\|Spearman\| < 0.3), типично для сдвига строк при merge |
| warning | `same_as_baseline` | порядок совпадает с `1-confidence` |
| warning | `class_pushed_down` | целый класс выпал из начала очереди |
| warning | `disagreement` | сильных расхождений больше 8% |
| info | `missed`, `overflagged` | конкретные боксы с самыми сильными расхождениями; бокс, поднятый вето, «лишним» не считается |

Если признаков детектора нет (например, запуск с ветки без `outputs/redetect_strong/`), мини-модель откатывается на 5 временных признаков и пишет об этом в отчёте. Если не удаётся обучить и её (или указан `--heuristics-only`), остаются только эвристики.

## 4. Объяснения и очередь оператора

Для каждого бокса причины подозрения словами:
- «ни один из 3 детекторов-контролёров не нашёл пары», «2 из 3 не нашли пары: спорный бокс»;
- «на этом месте детектор видит объект другого класса»;
- «вето экспертов: публичные COCO/поза-модели не подтвердили объект»;
- дубль, низкий confidence, нет опоры во времени, низкий бокс человека, край кадра, крошечный бокс.

В HTML это показано на первых 15 боксах сабмита, на расхождениях с мини-моделью и на боксах, сильнее всего сдвинувшихся при сравнении, с превью кадра. В каждой карточке есть готовая команда, которая открывает этот кадр в `tools/view_frame.py`. **Люди** вынесены в отдельный блок: это слабое место решения (AP по `person` около 0.65).

Отдельно аудитор сообщает долю боксов в ничьих и предлагает `tools/tie_break.py`, если в ничьих больше половины. Участники ансамбля находятся автоматически по файлам `pred_all*.csv`. Если появятся предсказания TTA (`*_flip`) или ученика, аудитор добавит рецепт «все участники, один к одному».

## Разбивка ничьих: `tools/tie_break.py`

**Проблема.** Балл лидера собран из грубых частей: D принимает значения 0, ⅓, ⅔, 1, вето — 0 или 1, confidence записан с двумя знаками. На 362 бокса приходится всего 102 разных значения, и **318 боксов стоят в группах с одинаковым баллом** (крупнейшая — 38 боксов). Внутри такой группы порядок для AP случаен.

**Решение без обучения.** Порядок между группами не меняется, внутри группы боксы упорядочиваются по `1 − iou_same`, усреднённому по участникам ансамбля: чем хуже бокс совпал с нашими детекторами, тем раньше.

```
новый = score · (1 − eps) + eps · (1 − iou_same),   eps ≤ 0.001 и меньше трети минимального зазора между группами
```

Инструмент проверяет, что порядок между группами сохранён и балл лежит в [0, 1]. На восстановленном лидере ничьи сокращаются с 318 до 21 бокса, люди выходят из ничьих полностью (140 → 0). Источник `iou_same` — закоммиченные `outputs/redetect_strong/pred_all*.csv`, вето и веса не нужны.

| На отложенных днях (одиночный детектор, без вето) | 25.10 | 26.10 | Среднее | Люди |
|---|---:|---:|---:|---:|
| формула «один к одному» | 0.9147 | 0.8629 | 0.8888 | 0.652 |
| **с разбивкой ничьих** | **0.9184** | **0.8661** | **0.8922** | **0.677** |

`compare_oof.py` с критерием «+0.003 к среднему, ни один день не хуже» → **пройден**. Парный bootstrap по кадрам: прирост в 99.2% повторов, 5–95% [+0.0009; +0.0090].

Оговорки:
- Проверено без вето и без ансамбля: их OOF-признаков нет в git. У того, у кого есть `outputs/expert_veto/train_features.csv` или `oof_features_ens-*.csv`, `--oof` сам покажет строки с ними.
- Оба дня уже использованы для многих решений, а локальные результаты здесь плохо переносятся на Public. Подтвердить может только отправка.
- Вариант с мини-моделью вместо `iou_same` дал столько же (0.8921), но в нём возможна утечка, поэтому выбран `iou_same`.

Запуск у того, у кого есть файл лидера: `python tools/tie_break.py submissions/redetect_strong_ens-base-s1-s2_1to1_veto_veto.csv`. Затем проверка: `python tools/submission_auditor.py <новый файл>`. Аудитор опознает его как «ансамбль один к одному + вето + разбивка ничьих».

## Сравнение OOF и критерий эксперимента: `tools/compare_oof.py`

У каждого эксперимента команды критерий фиксируется до запуска. Инструмент проверяет его одной командой и даёт таблицу для `reports/`. Проверка файла и AP берутся из `tools/evaluate_predictions.py`. Сверх этого добавлены:
- разница по дням и в среднем, AP по классам;
- парный bootstrap по кадрам внутри дня (обобщение `check_frame_stability.py` на любые два файла);
- вердикт `--min-gain X --max-day-drop Y` с причинами;
- доля ничьих у обоих файлов;
- `--markdown путь`.

Код выхода: 0 — пройден, 2 — не пройден, 1 — ошибка во входе. Опорным может быть любой OOF-файл или слово `baseline`.

## Сравнение двух сабмитов (`--vs`)

- Spearman, сколько строк изменилось, общий топ-20%, сдвиг по классам.
- Какая из двух очередей ближе к мини-модели.
- Боксы, сильнее всего поднявшиеся и опустившиеся.
- Вывод: «почти одинаковые — пара не страхует от ошибки выбора» или «разнообразная пара».

Какая очередь лучше, сравнение не говорит: это решает Public. Оно показывает, *чем* очереди отличаются.

## Ограничения

- Аудитор не знает ответов теста. `ok` означает «файл корректен, опознан и очередь правдоподобна», а не «AP будет высоким».
- Опознание по формуле работает только для пяти рецептов, которые можно восстановить из git. Ансамбль с учеником (нет `pred_all_st_strict.csv`) опознаётся только по SHA256. У файла с 0.90211 хеш в отчётах не записан, поэтому он опознаётся только по формуле.
- Признаки детектора на test посчитаны итоговой моделью на 84 кадрах, а мини-модель обучена на признаках дневных моделей на 42 кадрах. Распределения немного различаются.
- Пороги (8%, ±0.3, 0.995, топ/низ 10%) выбраны вручную, на метрике не подбирались.
- Локальные AP мини-модели посчитаны на тех же двух днях, на которых команда уже выбирала решения, поэтому они могут быть оптимистичны. Для этой задачи локальная проверка вообще плохо предсказывает Public.

## Что можно улучшить

- Положить в git признаки вето (`outputs/expert_veto/{train,test}_features.csv`) и хеш файла с 0.90211: тогда опознание станет полным, а `tie_break.py --oof` проверит разбивку вместе с вето.
- Запускать аудитор и разбивку автоматически в `redetect.py submit` перед каждой отправкой.
- `tools/analyze_strong_errors.py` считает D по старому правилу (`iou_same < 0.6`), а не «один к одному», как лидер. Стоит выровнять.
- Разбивка по дням теста.
