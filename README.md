# last_token

Решение кейса 1 хакатона: аудит детектора на кадрах камеры кафе. Нужно помочь оператору быстрее находить ошибочные предсказания.

## Текущее состояние

Датасет скачан в `data/rascar-hack-case-1/` и исключён из Git. В репозитории есть условие, скрипт исследования и [обзор данных](reports/data_overview.md). Baseline организаторов не требует обучения; собственного обученного решения пока нет.

## Условие простыми словами — TASK.txt

Детектор уже нашёл объекты и выдал для каждого класс, прямоугольник (бокс) и `confidence`. Мы не строим новый детектор: для **каждой существующей детекции** из `test.csv` выдаём `score` от 0 до 1. Чем выше балл, тем раньше оператор должен проверить этот бокс.

Например, детектор уверенно назвал сумку человеком. Даже при высоком `confidence` наш аудитор должен поднять такую детекцию в начало очереди. Кадр может содержать несколько боксов с разными оценками.

### Что считается ошибкой

Предсказанные и ручные боксы сопоставляются один к одному внутри кадра и одного класса. Требуется IoU ≥ 0,60. IoU — площадь пересечения двух прямоугольников, делённая на площадь их объединения. Сначала максимизируется число допустимых пар, затем суммарный IoU.

- Сопоставленный бокс: `error = 0`.
- Несопоставленный: `error = 1`. Причины — ложное срабатывание, неверный класс, плохая геометрия или дубль.
- **Пропущенный объект без предсказанного бокса в оценку не входит.** Найти его полезно для детектора, но задание оценивает другие ошибки.

Особенности ручной разметки: `person` охватывает всего человека, включая закрытые столом части тела; `nude_hands` — любые видимые голые кисти; `cup` включает чашки и стаканы, но не бутылки. Названия-алиасы приводятся по `scoring_policy.json`.

`table` исключён из test: в train у столов всего 3 ошибки на 472 бокса. При валидации столы тоже исключаем, но можем использовать как контекст.

### Метрика, отправка и правила

Метрика — **Average Precision (AP)** по метке `error`, вычисленная через `sklearn.metrics.average_precision_score`. Чем раньше в очереди оказываются ошибки, тем лучше. Это не accuracy и не mAP детектора; порог для бинарного решения выбирать не требуется. Балл задаёт порядок и не обязан быть калиброванной вероятностью. Одинаковые баллы обрабатываются как в sklearn.

`submission.csv` содержит `id,score`: каждый ID из шаблона ровно один раз, баллы конечны и лежат в [0, 1]. В текущем пакете нужно **362 строки**. Public и Private состоят из разных кадров; оцениваемое подмножество строк скрыто, поэтому сдаём ответ на все ID. Организаторы могут дополнить разметку Private внутри того же test и пересчитать отправки.

По TASK.txt: до 10 отправок в день, 2 можно выбрать для финала; дедлайн — **14 ноября 2026, 23:59 МСК**. Ручная разметка теста и ручная подстановка ответов запрещены. Тестовые изображения и контекст разрешены для предсказаний. Для публичных предобученных моделей в отчёте нужны название и URL весов. Финалисты сдают код и короткий отчёт.

Полное локальное условие: `data/rascar-hack-case-1/TASK.txt`. Копия страницы соревнования: [context/kaggle_case1.md](context/kaggle_case1.md).

## Как работает baseline.ipynb

1. Находит папку с данными через `DATA_ROOT`, Kaggle input или текущую директорию.
2. Читает train, test и шаблон; проверяет уникальность ID и отсутствие пересечения train/test.
3. Исключает `table`, присоединяет UTC-день по `frame_id` и считает AP отдельно за каждый день.
4. Присваивает тестовым детекциям `score = 1 - confidence`: чем меньше уверен детектор, тем выше подозрение.
5. Соединяет оценки с шаблоном по ID, проверяет количество строк и диапазон баллов, сохраняет `submission.csv`.

Обучения здесь нет. Оценка по дням — проверка одной фиксированной эвристики. Для своей обучаемой модели нужно обучаться на 25 октября и проверяться на 26-м, затем поменять дни местами.

| UTC-день | Боксов без table | Ошибок | AP постоянного балла | AP baseline |
|---|---:|---:|---:|---:|
| 25 октября | 68 | 34 | 0,500 | 0,861 |
| 26 октября | 130 | 75 | 0,577 | 0,765 |

Среднее двух дневных AP — **0,813**; это локальный ориентир, а не результат Kaggle и не AP на объединённых днях. Числа сверены по текущим CSV. Сохранённые outputs исходного ноутбука устарели: там встречаются другие количества боксов и 654 строки сабмита. Ориентируемся на повторный запуск, текущие данные и `reports/data_overview.md`.

Для локального запуска удобно открыть `baseline.ipynb` из папки датасета. Если запускаете из другой папки, задайте абсолютный `DATA_ROOT` до первой ячейки чтения данных. Ноутбук пишет сабмит в рабочую директорию ядра (на Kaggle — в `/kaggle/working`), а не обязательно рядом с собой.

## Machine pool: что это и как использовать

Это дополнительные кадры той же камеры за 25–26 октября с предсказаниями **того же самого детектора**. Ручных боксов и меток `error` в пуле нет. Пул не даёт 41 тысячу достоверных примеров ошибки: автоматические предсказания сами могут быть неверны.

Возможные применения: изучать типичные зоны и размеры объектов, устойчивость боксов во времени, обучать представления изображений, экспериментировать с псевдоразметкой. Для каждого такого применения прирост нужно подтвердить на отложенном дне.

Важные ограничения:

- Картинки пула — **640×360**, а координаты его предсказаний рассчитаны для **1280×720**. Для наложения боксов на эти картинки делим координаты на 2.
- Обычно кадры идут через 30 секунд, но есть пропуски. Используем реальные timestamp, а не номер строки.
- Если 26 октября — валидация, кадры пула за 26-е и контекст валидации не участвуют в обучении и подборе обучаемых представлений. При смене дней меняем и эту границу.
- По обзору прямого пересечения кадров основного train с контекстом и пула нет. Это не отменяет зависимости между близкими по времени кадрами.

## Краткие выводы из data overview

Источник: [reports/data_overview.md](reports/data_overview.md), опубликованный коллегой; это исследовательский отчёт, а не дополнительные правила соревнования.

1. **Размеченных примеров мало.** Из 670 train-боксов 472 — столы. Для нашей оценки остаются 198 боксов, 109 ошибок (55,1%) всего на 35 кадрах. Всего размечено 84 кадра, но остальные не содержат оцениваемых нестоловых детекций. В test 128 целевых кадров, однако строки `test.csv` относятся к 86: не каждый целевой кадр содержит нестоловые детекции. Это не признак недостающих изображений.
2. **Confidence — сильная отправная точка.** AP 0,861 / 0,765 заметно выше постоянного балла. Новые признаки должны улучшать эту эвристику на отложенном дне; сложность модели сама по себе ничего не гарантирует. Даже в диапазоне confidence (0,8; 0,9] доля ошибок около 35,5%.
3. **Классы ведут себя по-разному.** В train ошибочны 46/63 кистей, 21/33 чашек, 32/84 людей и 10/18 подносов. Имеет смысл проверять признаки класса и геометрии вместе с confidence. Редкие классы из общего policy в текущих оцениваемых таблицах не представлены.
4. **Основной резерв — геометрия и ложные срабатывания.** Эвристический разбор относит 56 ошибок к геометрии, 43 — к ложным срабатываниям, 9 — к чужому классу и 1 — к дублю. Это приблизительная диагностика, не официальная классификация. У ошибочных `person` медианная высота меньше — согласуется с проблемой обрезанных сидящих людей.
5. **Временной признак полезен, но слабее confidence сам по себе.** AP по отсутствию похожего бокса у соседей около 0,621 на объединённом train. Это другой набор оценки, чем отдельные дневные AP baseline, поэтому прямое сравнение ограничено. Даже при IoU с соседом >0,9 около 45,2% боксов ошибочны: ошибка может быть устойчивой. Сочетание признаков ещё нужно проверить по дням.
6. **Нужна аккуратная валидация.** На днях разные доли ошибок и мало активных кадров. Не делим случайные боксы одного кадра между train и validation. Не обучаемся на ручных test-метках, которых у участников нет. В отчёте 123 интервала пула больше минуты, а у части целевых test-кадров отсутствует сосед: отсутствие контекста обрабатываем явно.

Практический первый эксперимент: небольшая регуляризованная модель на `confidence`, классе, размерах и положении бокса; затем отдельно добавить соседние кадры и сравнить оба направления валидации. Это гипотеза по результатам обзора, не уже подтверждённое улучшение.

## Просмотр кадров и боксов

Из корня репозитория:

```bash
python -m pip install pandas pillow
python tools/view_frame.py
```

Скрипт читает CSV один раз и открывает браузер по адресу http://127.0.0.1:8765. Оставьте терминал работающим; для остановки нажмите Ctrl+C. Если браузер не открылся, перейдите по адресу вручную. HTML отдельно открывать не нужно: изображения и таблицы загружает локальный сервер.

Выберите Train, Test или Machine pool, введите `frame_id` (можно с `.jpg`) и нажмите «Открыть». Стрелки перебирают кадры по времени. Переключатель «Соседние кадры» показывает контекст рядом с текущим; для train/test связи взяты из `*_context.csv`, для пула — ближайшие доступные кадры. Время показано в UTC, интервалы могут отличаться от 30 секунд.

Ручные боксы синие и пунктирные. Машинные зелёные при `error=0`, красные при `error=1`, жёлтые без известной метки. Правильность берётся только из `train.csv`; на test и неразмеченном контексте она неизвестна. Столы по умолчанию скрыты. Есть фильтры по классу, ошибкам и слоям, таблица координат и сведения по нажатию на бокс. Координаты machine pool автоматически уменьшены под реальные изображения.

Сохранить отдельный кадр с боксами без запуска сервера:

```bash
python tools/view_frame.py --output reports/frame_preview.png
python tools/view_frame.py --split train --frame FRAME_ID --output reports/frame.png
```

Дополнительные параметры: `--data ПУТЬ` для другой папки данных, `--port 8766` если порт занят, `--no-browser` без автоматического открытия браузера. Для экспорта доступны `--no-human`, `--no-machine`, `--tables`.

## Обучение логистической регрессии

```bash
python -m pip install pandas numpy scikit-learn joblib
python tools/train_logreg.py
```

Скрипт проверяет три варианта: confidence; confidence + класс; confidence + класс + геометрия. Регуляризация фиксирована (`C=1`), масштабирование и кодирование класса обучаются отдельно внутри каждого разбиения по UTC-дням. Метрики и версии библиотек — в [reports/logreg_results.md](reports/logreg_results.md).

Первый эксперимент: средний AP baseline **0,812772**, регрессии с классом **0,774441**, с геометрией **0,778973**. Регрессия только на confidence сохраняет ранжирование baseline. Добавленные признаки ухудшили оба дня; улучшение пока не получено. Результаты не являются оценкой Kaggle.

Локально сохраняются `oof/logreg_*.csv` (честные предсказания на отложенных днях), `models/logreg_*.joblib` (модели, переобученные на всех 198 примерах) и `submissions/logreg_*.csv` (362 ответа на test). Эти файлы исключены из Git. Сабмиты автоматически на Kaggle не отправляются.

## Эксперименты с временным контекстом

`tools/train_temporal.py` сравнивает 7 конфигураций и их фиксированные смеси 50/50 с baseline. Лучший найденный вариант: компактная регрессия на confidence, IoU соседей, изменении confidence и пересечении боксов внутри кадра, смешанная с baseline. AP по дням **0,892035 / 0,788315**, среднее **0,840175** против **0,812772** у baseline. Чистая компактная регрессия тоже улучшила оба дня, но второй — лишь немного. Большие наборы признаков и деревья оказались слабее.
